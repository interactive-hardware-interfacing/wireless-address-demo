Hardware

Four identical boards, no wires between them, one LED each.

The three nodes run the same file and differ only by one number, MY_ID. The Firmware tab sets it for you (Install node 1 / 2 / 3), so a board is whichever node it was last installed as. Label them.

Parts

  • 4× Seeed XIAO ESP32-C3 with the u.FL antenna that ships with each.
  • 3× USB power banks (or any 5 V USB source) and USB-C cables; one data cable for the bridge.
  • Optional, per node: an LED and a 220 Ω resistor on D10, if the onboard LED is too small for the room.
  • Three labels: 1, 2, 3.

Things that bite

  • Two nodes installed as the same number both answer to it. Reinstall one from the Firmware tab; it takes a few seconds.
  • All boards pin Wi-Fi channel 6. A loose u.FL antenna hears nothing.
  • If you add your own wiring, keep anything tied to ground at power-up off D0, D8 (SCK) and D9 (MISO): on the ESP32-C3 they are boot-strapping pins.
  • A board that won’t take firmware: hold BOOT (B), tap RESET (R), release BOOT, then try again.

Tables are mirrored in wiring/wiring.md.

Put the firmware on the boards

One bridge, three nodes, each a single code.py written straight from this page. Chrome or Edge.

1. Plug in

Connect one XIAO ESP32-C3 over USB. If the instrument is connected to a board, this page disconnects it first.

2. Pick its job

Install bridge for the board that stays at the laptop. Install node 1, 2 or 3 for the others — the page sets MY_ID in the file before writing it. Pick the port named USB JTAG/serial debug unit.

3. Wait for the first line

The page writes code.py over CircuitPython’s REPL, checks its size and CRC on the board, reboots it, and waits for the bridge’s hello or the node’s “listening” line. Label the board and do the next one.

4. Connect

Back on the instrument, click Connect bridge and pick the bridge’s port. Nodes just need power. Or skip all of this: Try without hardware.

About this demo

What it shows, how to run it in front of a room, and how addressing works.

What it shows

Every device on a network has an address, and messages carry the address of who they’re for. Here, three identical boards each have an address; you pick a recipient and send a message, and only the addressed board lights up. Switch to All and it’s a broadcast — everyone hears it at once. It’s the idea behind the “to:” line on an email and the MAC address on everything on Wi-Fi.

Try this during the tour: send to Node 2 — only Node 2 blinks. Send to All — all three blink. Ask the group why Node 1 ignored the message meant for Node 2 (it checked the address and it wasn’t his).

How it works

You pick a recipient; the page sends SEND <1|2|3|ALL> <text> to the bridge → the bridge radios a packet carrying a target address. The Addressing switch is the lesson in one click. In node-id filter mode the frame is a broadcast: every node hears it (the heard counter ticks on all three, and they flash dim), but only the one whose id matches — or everyone, on broadcast — reacts (accepted, bright flash). In MAC unicast mode the bridge sends to that one node’s radio address: the others never receive the frame, their counters stay still, and the radio reports a real ACK. A broadcast has no ACK by design. The bridge learns each node’s MAC from the reports they send back, so send to All once before switching. See PROTOCOL.md.

The “sniff” aside: in id mode every node physically receives every packet — it just chooses to ignore ones not addressed to it, and the heard counter proves it. That’s why addressing is politeness, not privacy, and why encryption exists. Unicast narrows who receives the frame; it still isn’t secrecy.

Known quirks:

  • Broadcast (All) gets no ACK — that’s correct, not a failure. Only unicast is acknowledged.
  • In node-id mode a “unicast” is still a broadcast frame filtered by id, so there is no radio ACK; the node’s own report (“Node 2 got it”) is the confirmation. Switch to MAC unicast for a real ACK.
  • MAC unicast to a node the bridge hasn’t heard from yet gives an error and sends nothing — send to All first.
  • If a node is off or out of range, nothing echoes back. Good teaching moment.
  • The page lights a node the instant you click Send, before the echo arrives, so it feels responsive; the log line is the truth.
